# Bilibili Clear · 极简B站

一次安装，直接使用。Bilibili Clear 内置 37 项功能，覆盖首页、视频、动态、评论、直播和下载；每项功能都保留独立开关与选项。

由 [NeverOvO](https://github.com/NeverOvO) 维护，基于 [Bilibili Evolved](https://github.com/the1812/Bilibili-Evolved) 开发。当前分支：**beta · 3.2.0.8（Beta 8）**。

## Beta 体验

本分支开发关注首页与竖屏模式，正式版仍在 [master](https://github.com/NeverOvO/Bilibili-Clear/tree/master)。Beta 安装链接与后续自动更新均指向 `beta`，不会向正式版用户推送测试功能。保持原脚本名称与设置存储；安装时选择覆盖现有 Bilibili Clear，避免同时启用两个副本。

- **原版精简**：保留现有首页和全部原功能，默认继续使用此模式。
- **UP极简模式**：左下角一键切换原版 / 极简。默认显示按天分组的视频网格；顶部 GitHub 图标与 NeverOvO 名称直达本仓库。“视频 / 帖子”标签与批量添加入口在同一行，保留实际同步结果，观看标记说明集中在本页。只显示已确认关注的作者，不展示推荐、直播或转发。
- **连续浏览**：首次依次读取 4 页关注动态，下滑接近底部时继续加载；接口提前到末尾时停止。视频与帖子共用已加载的数据，切换标签保留内容及各自滚动位置，同页切回原版或竖屏模式后也可继续浏览。主动刷新、整页刷新或更换账号会重新读取。
- **视频状态**：观看记录位于封面底部，紧邻播放量；无记录为黑底白字，实际播放位置与时长使用蓝字。达到“看完了”规则只影响完成遮罩，不改写真实观看时间；仅在接口明确标记已结束或播放器实际结束后，以绿字显示总时长 / 总时长。视频封面与动态顶部的充电、专属徽标统一使用粉色。
- **稍后再看**：未完成视频可通过封面右上角添加，成功后显示蓝色书签勾选图标；已显示完成遮罩的视频隐藏该按钮，批量模式仍可手动选择尚未在列表中的条目。单条添加不显示批量汇总，已有条目在批量模式中只显示文字。按天添加仍只包含当前已加载、尚未看完的视频。后台旧列表快照不会覆盖本次添加成功的状态，顶部数量入口打开 [原版稍后再看列表](https://www.bilibili.com/watchlater/list#/list)。
- **帖子阅读**：按天分组的瀑布流保留标题、正文和完整比例图片；固定卡片所在列，利用已知图片尺寸占位，在接近阅读区域前加载正文与图片。内容补齐时尽量保持阅读位置，卡片增加柔和阴影和边界颜色；点击“查看原帖与评论”进入原版页面。识别到摘要时继续补取原始 Opus 正文，不因已有文字就判为完整；未能补齐时保留原文入口和非完整状态。图片尺寸缺失或详情内容扩展时仍可能产生局部高度变化。
- **帖子归并**：疑似营销动态进入顶部默认折叠的“疑似广告”分组，可展开阅读并打开原帖。本地规则结合营销语境、行动引导和优惠红包等信号；在已加载内容中比较 7 天内的较长正文与配图，仅在双方正文都完整时进行近似归并，避免只因配图相同就合并不同帖子；归并后保留一份并显示数量。普通抽奖话题或简短问候不会单独触发归并。规则可能误判或漏判，不删除账号中的动态。
- **原生抽奖弹窗**：只有正文包含 B 站原生抽奖节点及有效抽奖 ID 时才显示“参与抽奖”。点击后在当前列表内打开独立弹窗，加载同源 B 站官方抽奖页面，首页不跳转；等待官方页面实际内容出现后才结束加载，登录与参与操作由原生页面处理，脚本不自行提交。异常时可从后备入口打开原帖。抽奖动态使用淡透明粉色背景与粉色悬停边框，普通“互动抽奖”话题不会自动识别为原生抽奖。
- **封面下载入口**：本版隐藏视频卡片上的下载按钮，保留底层实现；原有下载组件继续可用。
- **网页标签**：保留完整原标题，仅在末尾追加一个 `Clear`，并随原生标题更新；下载文件命名使用未添加标记的原始标题。
- **启动体验**：记住关注极简模式后，脚本启动时提前隐藏原版首页，极简页面挂载后接替显示。启动异常会自动恢复原版；脚本管理器注入过晚时仍可能短暂出现原页面。
- **竖屏模式**：这是此前推荐播放视图的新名称，功能与设置延续。使用网页推荐源和原版播放器，沿用当前 B 站登录会话。队列剩余 4 条时提前补充至约 10 条，当前与下一条播放器固定在两个槽位中，切换时复用而不移动 iframe，并隔离旧页面回调，避免把加载过程误判为离开当前视频；真实切换到其他视频或分 P 的保护继续保留。后续封面提前加载。下一条播放器不主动播放，默认有声在切换激活后生效；浏览器阻止自动播放时显示点击入口。支持上下键、滚轮和滑动切换。首次封面最多覆盖 3 秒，随后露出原生界面；原生重试成功后清除可恢复错误。等待下一条时返回、屏蔽或隐藏页面会取消旧跳转意图，不让稍后的请求结果驱动过时切换。网络、过滤结果和原生播放器仍可能造成等待。
- **内容过滤**：过滤广告卡、直播和番剧，并通过分类、标题和标签排除可识别的短剧。无标记的植入广告或短剧不能保证全部识别，可手动屏蔽 UP。历史和屏蔽列表按登录账号存储在脚本管理器中。

本轮已进行源码静态审计，范围与发现见 [Beta 8 审计记录](doc/beta8-audit.md)；发布使用统一构建流程，未执行测试、类型检查、lint 或浏览器实测。接口和登录体验由 Beta 用户安装后确认。普通视频页本地记录与主站播放器的历史同步是两种来源，竖屏模式退出后可点“同步观看记录”。全部数据请求使用当前账号权限，接口报错会显示重试入口，不以其他推荐内容代替关注列表。

要回到正式版，安装 [master 版本](https://raw.githubusercontent.com/NeverOvO/Bilibili-Clear/master/dist/bilibili-clear.user.js)，在脚本管理器中确认覆盖较高版本；正式版自动更新地址也随之恢复。现有功能设置继续沿用，Beta 新增项在正式版中不启用。

## 观看标记与同步范围

已开始观看且进度达到 95%，或剩余不足 30 秒时，可显示“看完了”遮罩。此规则不把真实播放位置改成总时长：例如实际看到 9:40 / 10:00，即使已显示遮罩，仍保留蓝字 9:40 / 10:00。只有历史接口返回结束标记 `-1`，或播放器触发实际结束事件 `ended`，才用绿字显示总时长 / 总时长。多 P 视频逐段判断，全部分 P 达到完成规则后才给整条视频盖章。分 P 上下文读取失败时进行有限重试，不因一次失败就永久停止补齐。没有命中记录只表示当前未读取到记录，不代表从未观看。

本地记录不按天过期，按最近观看时间保留最多 1000 个视频。进入首页自动同步最近 90 条；手动“同步观看记录”向前补充最近 7 天，每次最多读取 30 页 / 900 条。页面显示实际同步条数与覆盖时间，接口末尾、返回范围和本地容量会限制结果。当前页面内复用连续覆盖范围与分页游标，读取失败保留已经取得的记录。顶部“观看历史”可打开原版历史页面。

按天添加稍后再看仅包含当前已加载的当天未看完视频。每批按发布时间从新到旧提交并错开添加时间，因此本批新增条目在原版默认“最近添加”排序下，发布时间较早的排在前面；已有条目跳过并保留原位置。

## 安装

在桌面浏览器中安装脚本管理器后，打开以下链接并完成安装：

**[安装 Bilibili Clear](https://raw.githubusercontent.com/NeverOvO/Bilibili-Clear/beta/dist/bilibili-clear.user.js)**

安装后刷新哔哩哔哩页面。点击左下角的 Bilibili Clear 按钮打开设置窗口，按分类搜索功能、调整开关和选项，或导入设置，无需逐个下载组件。窗口中的“页面功能”集中显示当前页面可用的操作。可通过关闭按钮、Esc 或点击背景遮罩关闭窗口。

已安装 Bilibili Clear 3.x 的用户可通过 Beta 链接覆盖更新，现有设置继续沿用，无需重新导入。

从 Bilibili Evolved 或 HomeFix 切换时，请先关闭旧脚本，避免同时修改同一页面。安装不同名称的脚本不会自动转移旧脚本的存储数据。

## 使用说明

- 默认启用内置功能，按页面范围运行；无需使用的功能可在设置中关闭。
- 首页删除广告功能同时隐藏“检测到您的页面展示可能受到浏览器插件影响”的提示横幅。
- “简化首页”中的“推荐视频流”控制新版首页整片推荐内容；轮播图有独立开关。
- 删除动态、签到、下载、点亮粉丝勋章等功能由用户点击触发，安装脚本不会自动执行这些操作。
- 下载和账号功能使用当前账号已有权限，受登录状态、内容权限和平台接口限制。
- 额外扩展接口继续保留。项目自带功能随本体更新，不能通过外部组件覆盖；额外扩展自行维护来源。

## 迁移已有设置

支持导入 Bilibili Evolved v2、HomeFix 和 Bilibili Clear 导出的设置文件。

1. 在旧脚本中导出设置。
2. 关闭旧脚本，从本页安装 Bilibili Clear。
3. 打开设置面板中的“关于”，选择“导入设置”。
4. 导入完成后刷新页面。原功能开关、布局、快捷键及个人设置会迁移到新版本。

迁移使用原功能 ID，将已内置组件的设置移入内置存储，并移除这些组件的旧代码和独立更新记录。配置结构不符合要求时会显示具体字段错误，不先覆盖现有设置。

也可以在本地转换文件，原文件不会被覆盖：

```sh
node dev-tools/migrate-settings.mjs --input /path/to/settings-homefix.json --output /path/to/settings-bilibili-clear.json
```

个人设置文件可能包含黑名单、收藏夹状态及额外扩展信息，请勿提交到公开仓库。公开发行版只包含通用功能与布局默认值。

## 更新与回退

本体及 37 项内置功能由本仓库统一发布，通过脚本管理器获取更新。上游改动经过选择性合并后进入新版本，不会直接覆盖当前内置功能。

每个正式版本提供 Git tag、[Release](https://github.com/NeverOvO/Bilibili-Clear/releases)、更新说明和安装文件。需要回退时，按[回退指南](doc/rollback.md)操作。

B 站页面结构和接口变化可能影响功能。反馈时请提供页面地址、脚本版本、浏览器及脚本管理器版本、具体操作与错误信息；不要提交 Cookie、Token 或完整个人配置。

## 浏览器与脚本管理器

面向桌面端 Chromium / Firefox / Safari，以及 Tampermonkey、Violentmonkey、Stay。Safari / Stay 的组件加载接收者问题已作兼容处理，不同组合的功能表现仍取决于浏览器和脚本管理器能力。

3.2.0.8 Beta 8 提供发布构建，本轮完成源码静态审计；未执行测试、类型检查、lint 或浏览器实测。帖子占位与竖屏模式预加载用于减少等待和布局变化，不保证慢网络下零等待。Safari / Stay 的实际效果由用户安装后确认。移动端不在当前适配范围。

## 开发

使用 Node.js 22 和项目指定的 pnpm：

```sh
pnpm install --frozen-lockfile
pnpm --dir registry install --frozen-lockfile
pnpm run build
```

输出为 `dist/bilibili-clear.user.js`，全部默认功能随安装包交付。业务实现继续位于 `registry/lib`，核心和设置框架位于 `src`。新增功能通过内置清单、加载入口和必要迁移接入。

开发与贡献流程见 [CONTRIBUTING.md](CONTRIBUTING.md)，本地调试见 [DevServer 文档](dev-tools/dev-server/README.md)。
