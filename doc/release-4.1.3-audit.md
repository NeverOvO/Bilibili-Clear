# Bilibili Clear 4.1.3 发布审计

2026-11-19。基线为上个正式版 `v4.1.1`（`7ee6aac96`），审计至 `v4.1.2.5`（`4a3d91753`），共 13 个提交。审阅了源码、构建配置、脚本权限、外部采集器和发行文档。发行脚本和 source map 由正式版源码重新构建。

## 审计中发现并修复的问题

| 触发条件 | 影响 | 4.1.3 的处理 |
| --- | --- | --- |
| 首屏样式还在下载或等待插入，用户关闭组件或再次开启 | 旧样式可能随后出现，留在待挂载的片段中，或覆盖较新的样式 | 每个样式名只接受最新加载结果，卸载同时清理待挂载节点。Shadow DOM 样式在解析完成后复核请求身份，移除旧实例时只释放它自己的样式和订阅 |
| 整个评论容器被移除，或者在评论区初始化完成前离开页面 | 原来的父节点监听可能收不到移除事件，留下监听或重复通知 | 按评论区元素去重，由已有的页面节点监听释放断开连接的评论区。初始化被取消时同时结束等待 |
| 外部扩展按原始函数注销全页 DOM 观察回调 | Beta 的计时包装改变了回调身份，扩展可能无法取消订阅 | 公开列表保存原回调，内部按需转发到计时包装 |
| Safari 从后退缓存恢复较早页面，其间同一标签页产生了新记录、清空日志或改变开关 | 旧页面可能覆写较新的诊断记录和选择 | 页面恢复时先从会话存储同步，重新关联仍保留的会话，再恢复前台采集 |
| 日常使用继承了 Beta 默认启用的卡顿采集 | 前台每秒有心跳，悬停和聚焦也会触发采集 | 正式版默认关闭，按标签页和网站来源手动开启。有保存的 Beta 日志仍可导出 |
| macOS 采集器收到大量系统日志，普通消息队列已满 | 采样完成消息可能丢失，使后续采样一直处于忙碌状态 | 单独保留一个完成通知槽位，主循环优先处理完成通知并回收样本 |
| 后台任务提交后一直没有写入心跳 | 原错误文件可能包含 `launchctl print` 输出的用户环境 | 该错误文件只记录未收到心跳及查询的退出码 |

## 首页与渠道

- 审阅了 html2canvas 忽略标记的添加与撤销、可见列表与折叠状态、截图 iframe 的初始化入口，以及切换首页模式后广告扫描的取消与恢复。
- 审阅了个人空间的登录与未登录分支、播放器监听的路由范围、弹窗和 Shadow DOM 的订阅清理。依赖清单、锁文件、用户脚本授权和跨域访问声明与 4.1.1 相同。
- 正式渠道使用 `master`，产品版本为 `4.1.3`，高于最后的 Beta 版本 `4.1.2.5`。外部扩展兼容基线为 `2.11.5.2`。可选采集器由用户单独启动，发行附件只包含工具和说明。

## 验证范围

本轮按项目执行规则进行人工源码审计和发行构建。回归用例的模拟依赖、面板默认状态和版本比较已随源码更新。本轮未执行测试、类型检查、lint、Safari 实测或 launchd 实测。

`pnpm run build` 使用现有依赖完成构建。运行器提示忽略旧格式的 pnpm 依赖覆盖配置，本轮没有重新解析或安装依赖。产物内嵌的源码提交为 `724136ad6`。核对了脚本头中的版本、下载地址、更新地址、图标、授权范围和 source map 地址，以及采集器 ZIP 的文件清单与三个启动、状态、停止入口的执行权限。

Safari 试用者反馈 Beta 5 近期运行较稳定。现有证据尚不足以把整页卡死归因于单一路径，也没有正式版加载速度的对比测量。
